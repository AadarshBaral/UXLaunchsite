# Notion-Style Admin Panel

A design spec for building clean, information-dense admin panels / management dashboards that look like they were designed by a senior product designer, not generated by an AI template. The reference pattern is a Notion-like database/table view (see product-management table example: Product ID, Name, Category, Stock, Total, row checkboxes, filter bar).

Read this file fully before placing a single frame. Every screen produced under this skill must be checked against the **Anti-Slop Checklist** before being shown to the user.

---

## 1. Core Layout Rules (non-negotiable)

- **Left sidebar for navigation.** Navigation lives in a **fixed-width left sidebar** (≈240–260px), not a centered top nav bar. It holds primary nav sections/links stacked vertically, labels always visible (no icons-only collapsed rail by default). Icons next to labels are optional and must stay monochrome per the Anti-Slop Checklist.
- **Top bar is minimal**, sitting beside the sidebar — just page title/breadcrumb on the left and user/notifications (icon-only, monochrome) on the right. It never carries primary navigation.
- Sidebar gets a hairline **right border** (`#E6E6E8`) and a subtly off-white background (`#FAFAFA`) to separate it from the white content area — no shadow.
- A collapsible sidebar (icon-only collapsed state) is fine if requested, but default to expanded with visible labels.
- **Max content width: 1280px.** The dashboard body (table, filters, cards, everything below the top bar) is constrained to a 1280px container within the content area to the right of the sidebar, centered with equal margins. Never let tables or content stretch full-bleed on large screens.
- **Max corner radius: 8px, anywhere in the UI.** Buttons, inputs, cards, modals, avatars-in-squares, badges — nothing exceeds 8px radius. No pill-shaped buttons, no fully-rounded cards. Small elements (checkboxes, small icon buttons) can use 4–6px. This is a hard ceiling, not a target — smaller is fine, larger is not.
- **Row-click navigates to a dedicated page by default.** Clicking a table row routes to its own URL (e.g. `/items/[id]`) showing the full record, with its own back link and header actions — not a slide-over drawer. A dedicated page is bookmarkable, keeps browser back/forward working, and doesn't fight the sidebar for width. Reserve a right-side slide-over (~400–480px) only for genuinely lightweight peeks — a quick glance at 2–3 fields where a full page would be overkill — never as the default drill-down pattern.
- **Sequential / staged workflows get a vertical step sidebar, not horizontal tabs.** When content is organized as ordered stages (a wizard, a phased workflow, onboarding steps), list the stages top-to-bottom in a left sidebar — each row showing a status dot and a progress fraction (e.g. `2/4`) — instead of a horizontal tab strip. Horizontal tabs overflow and clip on real content (five-plus stages with real titles never fit one row), and a vertical list reads as a progress narrative in a way a tab row doesn't. This sidebar can be the same one used for primary nav, or a second nested one scoped to the current section.
- **Density over decoration.** Default to compact row height (36–44px), tight but legible spacing, and show as much real information as possible without feeling cramped. This is a tool for power users, not a marketing page. Prioritize scanability: consistent column alignment, numbers right-aligned, text left-aligned.

## 2. Anti-AI-Slop Checklist

AI-generated UIs have a recognizable "tell." Before finishing any screen, go through this list and remove every violation. These are the most common failure patterns:

### Icons & Color
- ❌ **Colored icons everywhere** (a rainbow of blue/green/purple/orange icons in the sidebar or nav). ✅ Icons are monochrome — use the neutral/gray-900 (or gray-500 for inactive) ink color, matching text. Color on an icon should be as rare and intentional as color on a heading.
- ❌ Icons wrapped in colorful rounded square "chips" or gradient badges as decoration. ✅ Icons sit plainly next to text, no background container unless it's a real interactive button (and even then, neutral background).
- ❌ Gratuitous gradients on buttons, headers, or cards. ✅ Flat fills only. One accent color used sparingly (primary CTA, active sidebar item, links) — everything else neutral gray/black/white.

### Status & Tags
- ❌ **Colored pill/badge for every status** (green pill "Active", red pill "Failed", yellow pill "Pending" — the classic AI-slop status column). ✅ Use a **small colored dot + plain text label**, no background fill, no border-radius pill. E.g. `● Active` (green dot, black text), `● Failed` (red dot, black text). The color lives only in the dot, never floods a whole badge shape.
- ❌ Overloading status color meaning (using red/green/yellow AND bold AND icon AND badge all at once for one state). ✅ Pick one signal (the dot) and let typography stay neutral.

### Cards & Containers
- ❌ Heavy drop shadows, glassmorphism, or floating cards with big blurred shadows to "add depth." ✅ Use a 1px hairline border (subtle gray, e.g. #E5E5E5 / similar) instead of shadow. Shadows, if used at all, are extremely subtle (barely-there, for popovers/modals only).
- ❌ Every section wrapped in its own bordered/shadowed card, creating "card soup." ✅ Use whitespace and thin dividers to separate sections; reserve cards for genuinely discrete, draggable/movable objects (e.g. a kanban card), not for basic page sections.
- ❌ Large, loud empty states with big illustrations and multiple CTAs. ✅ Small, quiet empty states: one line of text, optionally one understated action.

### Buttons & Inputs
- ❌ Overly rounded ("pill") buttons, big chunky primary buttons with heavy shadows. ✅ Rectangular buttons, max 8px radius, flat, modest padding (e.g. 8–12px vertical, 12–16px horizontal).
- ❌ Too many primary (filled/colored) buttons on one screen competing for attention. ✅ One primary action per view max; everything else is a plain/secondary/ghost button (border or text-only).
- ❌ Placeholder-heavy forms with giant labels and huge gaps between fields. ✅ Compact form fields, labels either inline or small/muted above the field, sensible field height (~36–40px).

### Typography
- ❌ Excessive font-weight/size variation (huge bold headers next to random other bold text everywhere) to create "hierarchy" via brute force. ✅ Restrained Tailwind scale only (`text-sm` body/table, `text-2xl` page title). Weight used sparingly — most text `font-normal`, `font-medium` for emphasis, `font-semibold` reserved for Merriweather page titles only.
- ❌ Mixing more than two font families, or using Merriweather anywhere outside page titles (nav, buttons, table cells, body copy stay Raleway). ✅ Strict two-font system: Merriweather for display, Raleway for everything functional.
- ❌ Center-aligned body text and paragraphs (common AI default that reads as unpolished). ✅ Left-align all body/table text; only center truly symmetric elements.

### Tables & Data
- ❌ Every column decorated with an icon, avatar, or colored tag just to "look rich." ✅ Only add visual elements (avatars, icons) where they carry real information (e.g. a product thumbnail, a user's avatar) — not decoratively on every column.
- ❌ Inconsistent row heights, misaligned checkboxes, numbers left-aligned. ✅ Strict grid alignment: checkboxes in a fixed-width first column, numeric columns right-aligned, consistent row height throughout.
- ❌ No visible way to sort/filter, or (opposite failure) an overloaded toolbar with 10 buttons. ✅ A single clean toolbar row above the table: view name, a search input, a Filter control, a Columns control — same restrained set as the reference (Table / Columns / Search / Filter), plus one primary action on the right (e.g. "+" to add).

### General "AI Slop" Tells to Avoid
- ❌ Overuse of emoji as icons in a professional admin tool.
- ❌ Randomized or overly playful copy ("Oops! Nothing here yet 🎉") in a serious internal tool.
- ❌ Inconsistent spacing (not on a shared spacing scale like 4/8/12/16/24/32).
- ❌ Mixing multiple border-radius values inconsistently across similar components.
- ❌ Decorative background patterns, blobs, or illustrations behind data-dense screens.
- ❌ Overly saturated or neon accent colors. Keep the accent close to the reference: restrained near-black (#0F1115 / #111827-ish) for ink, and one muted accent (e.g. a dark teal/navy like the reference "+" button) for the single primary action.

## 3. Design Tokens

Use these as the baseline; adjust hue only if the user gives brand colors, but keep the *values/restraint* the same.

**Color**
- Background: `#FFFFFF`
- Sidebar / table header bg: `#FAFAFA` or `#F7F7F8`
- Border / divider: `#E6E6E8` (hairline, 1px)
- Text primary: `#111214`
- Text secondary / muted: `#6B7280`
- Text disabled: `#9CA3AF`
- Accent (single, sparing use — primary button, active sidebar item, links): one restrained dark accent, e.g. `#0F3D3E` teal or brand color if provided
- Status dots only: green `#22A06B`, red `#E5484D`, amber `#F5A524`, gray `#9CA3AF` — dot only, never as a fill/background

**Radius**
- Max 8px (cards, modals, inputs, buttons)
- 4–6px for small controls (checkboxes, small icon buttons)
- Never fully rounded except true circles (avatars, status dots)

**Spacing scale**
- 4, 8, 12, 16, 24, 32, 48 — pick from this scale only

**Typography**
- Fonts: **Merriweather** (serif) for page titles / display headings only. **Raleway** (sans) for everything else — sidebar nav, top bar, table, body, labels, buttons. Exactly two fonts, no substitutions, no falling back to system UI or Inter.
- Use Tailwind's default type scale and weight utilities — pick from these only, never a one-off px value:
  - Page title: `text-2xl font-semibold` (Merriweather)
  - Section label: `text-xs font-medium`, muted color, optional `tracking-wide` if uppercased — sparingly (Raleway)
  - Sidebar nav item: `text-sm font-medium` (Raleway); active item gets the accent color, not a filled background pill
  - Table header text: `text-xs font-medium`, muted (Raleway)
  - Table cell text: `text-sm font-normal` (Raleway)
  - Emphasis within a cell (e.g. row title): `text-sm font-medium` (Raleway)
  - Body/UI text: `text-sm font-normal` (Raleway)
  - Muted/secondary text: `text-sm font-normal` at the muted text color

**Elevation**
- Default: none (use borders)
- Popover/dropdown/modal only: very subtle shadow, e.g. `0 4px 12px rgba(0,0,0,0.08)`

## 4. Page Structure Template

1. **Left sidebar** — fixed width ~240–260px, full viewport height, hairline right border, subtly off-white background. Logo/wordmark at top, grouped nav sections stacked vertically, account menu pinned to the bottom.
2. **Top bar** — minimal, ~56–64px, sits beside the sidebar (not centered nav). Page title/breadcrumb (left), notifications/account icons only (right, monochrome).
3. **Page container** — max-width 1280px within the remaining content area (right of the sidebar), horizontal padding ~24–32px.
4. **Page header row** — page title (left, Merriweather `text-2xl font-semibold`), single primary action button (right, e.g. "+ New").
5. **Toolbar row** — view switcher (e.g. "Table"), secondary controls ("Columns"), search input, "Filter" control — all left-to-center, kept compact; nothing colorful.
6. **Data table** —
   - Fixed-width checkbox column
   - Sortable column headers (subtle caret, muted color, only visible/darkened on hover or active sort)
   - Left-align text columns, right-align numeric columns
   - Status columns use dot + text, never a pill
   - Row height ~40–48px, hairline row dividers (or zebra striping only if the user explicitly wants it — default to hairline dividers, no striping)
   - Hover state: subtle background tint (`#FAFAFA`), cursor pointer, whole row clickable
7. **Row click → dedicated page** — navigate to the record's own route, showing full fields grouped logically, with a back link and header actions (status control, export/menu) in place of a slide-over's close button. Use a right-side slide-over (~400–480px) instead only for a genuinely lightweight peek.
8. **Staged workflow (if applicable)** — when the section itself is one stage of a larger sequential process (see Core Layout Rules), nest a vertical step list in the sidebar for that record: each stage as its own row with a status dot and progress fraction, linking to that stage's own page.

---

## 5. Before Delivering — Final Pass

Before showing the design to the user, explicitly re-check:
1. Is navigation living in the left sidebar, not a centered top nav? Fix if nav has drifted into the top bar.
2. Is every icon monochrome (no rainbow of colors)?
3. Is every status shown as dot + text, with zero colored pill/badge backgrounds?
4. Is any corner radius above 8px? Fix it.
5. Is the content container wider than 1280px on large screens? Constrain it.
6. Does clicking a row navigate to that record's own page (not a slide-over, unless it's a deliberate lightweight peek)?
7. Are staged/sequential sections listed vertically with status dots and progress fractions, not as horizontal tabs?
8. Is there more than one loud/filled primary button on screen? Reduce to one.
9. Any drop shadows outside of popovers/modals? Replace with hairline borders.
10. Are only Raleway and Merriweather in use, with Merriweather confined to page titles?
